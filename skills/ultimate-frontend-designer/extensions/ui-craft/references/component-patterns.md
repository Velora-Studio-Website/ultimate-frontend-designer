# Component field notes

Open `../assets/component-lab.html` directly in a modern browser. The adjacent CSS and deferred vanilla JS are the only dependencies. No server, external font, package, request, upstream asset, or logo is needed. Everything is original demo content; prices, events, metrics, delivery details, saves, and archives are illustrative. The top banner states this boundary. Generated raster assets are unnecessary: the artwork is editable inline SVG and CSS.

## Choose and extract one pattern

Copy **only the chosen** `article[data-pattern="stable-id"]`, its specific CSS rules, and its interaction handlers into the existing product. Map the lab's tokens to the destination tokens/framework. Bring required helpers (`$`, `on`, `say`) or replace them with the destination's equivalent. Include shared form/focus/dialog/table rules only when that pattern needs them. Preserve labels, headings, statuses, and ARIA relationships. Rename DOM ids and linked `for`, `aria-controls`, `aria-labelledby`, and `aria-describedby` values together if multiple instances will exist.

Do not import the whole laboratory, initialization inventory, demo datasets, page scaffold, all event listeners, or all tokens into a product. A framework implementation should use its own state and lifecycle. The lab script expects all 19 examples to exist and is not a drop-in library. Inspect the artifact itself; do not execute or evaluate the whole Skill in a browser. The decorative foldout is optional and independent of the 19 patterns.

Every pattern's container uses the same stable value for `id` and `data-pattern`. Initialization checks all DOM ids and pattern keys for duplicates, checks matching container identities, and expects exactly 19. Results appear near the top. This is an inventory guard, not browser validation or a test suite.

## Reachable demo states

All states are attainable without APIs. Toggle focus, radios, expansion, media palette, checklist, billing, comparison, timeline, or tabs directly. Use the delivery and archive buttons to exercise native dialogs and Escape. Add activity repeatedly to observe the five-event bound. Dismiss then Undo the notice. In Favorites, enable “Demo: simulate storage failure” and activate Save/Remove; disable it to retry. In Settings, edit, submit whitespace to exercise trimmed validation, or enable “Demo: simulate save failure” before Save; disable it to retry with the draft retained. Native required/minlength validation may also prevent invalid submission before the JS handler runs. For data, choose Empty or Simulated load error; Retry returns to Ready. A file picker is the only state requiring a user-owned local file; an oversized, empty, or wrong-extension file demonstrates rejection if the OS picker allows overriding the accept filter.

## Optional contained decoration

The native `details#effects` foldout contains exactly three decorative tiles: `.light-trail`, `.dot-field`, `.flow-gradient`. They are not pattern inventory entries. Each clips and contains its paint, is hidden from assistive technology, and has a static readable label. A visible pause/resume control pauses all animations. Closed foldouts pause animation; `prefers-reduced-motion: reduce` disables it entirely and positions the trail statically. Extraction requires the foldout/effect CSS and pause handler only if animation is retained. Do not attach decorative motion to essential feedback or import the whole lab for these effects.

## Accessibility, safety, and verification boundary

Native controls provide keyboard behavior; all buttons have explicit functional names. Dialogs require modern native `HTMLDialogElement.showModal` support and use explicit close-event focus restoration. The archive flow restores focus to its newly available Restore button when the original opener is hidden. Hidden content uses the `hidden` attribute, with a CSS override that preserves its semantics. Tabs implement the horizontal tab keyboard model. Focus indicators, live status messages, a skip link, semantic heading levels, table captions/headers, and associated form labels are included.

Responsive rules target a three-column desktop collection at 1440px and one column at 360px. Shared two-column and list-detail layouts collapse before narrow screens; dialogs and inputs are width bounded. These are implemented intentions; actual visual, keyboard, responsive, screen reader, and browser checks belong to the primary maintainer's browser pass.

Dynamic user input, file names, and table values are assigned with `textContent`; no HTML injection, eval, external dependency, or network API is used. Storage uses only `ui-craft-pro:component-lab:quiet-workspace:v1`; storage availability/persistence under `file:` URLs varies by browser, and same-page tabs are not synchronized. Settings, pagination, notices, and archive state reset on reload. Upload checks metadata only, not file signatures or safety. No backend, true upload, payment, background timer, analytics, or production save is implemented.

Authorized static verification: `node --check ../assets/component-lab.js` (run from this directory, or use its absolute path). No test suite is supplied. Syntax success establishes parsing only; it does not establish runtime, visual, accessibility, or human acceptance.
