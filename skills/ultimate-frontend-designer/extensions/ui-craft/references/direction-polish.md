# 方向收敛与组件精修

## 先确定比较对象

从用户任务、内容密度、品牌和参考推导方向，写下一句能指导取舍的体验意图。判断页面主要是说服、操作、阅读还是体验；操作型界面以对象、数据和操作开场，不自动加营销 Hero。没有用户研究时将动机与画像标为假设。

未定方向时，提出有实质区别的少量候选；用户已指定一个方向或授权自主决定时沿用，不重复询问。候选共用内容、主任务、设备与约束，比较信息骨架、字形和尺度、色彩面积、空间密度、主视觉关系，不能只换配色。差异足够后停止扩散。

方向卡记录：用户来做什么；首屏优先看什么；信息骨架；字体与中文回退；颜色分工；主视觉来源；有意义的记忆点；主动克制；移动端重排；可观察的验收点。完整建站先用宿主图片流程形成设计稿，再通过 [对比工具](tooling.md) 比较。

眯眼或缩小查看块面只检查重心和节奏，不证明文字或操作可用。文字遮罩只能用于视觉层级对照，不得遮掉数据图形后宣称其正确。所选方向进入现有设计规范和 tokens，不再维护第二套权威设计文件。

## 已有组件如何精修

先固定组件的输入、输出、可达状态、内容上限与容器约束。保存基线图和可操作入口，明确缺陷属于信息、布局、交互还是视觉。不要以重写整个组件树代替局部诊断。

按影响次序处理：主任务或状态难识别；内容被裁切或控件不可达；排版与对齐；间距节奏；装饰。保持语义、键盘操作与既有业务契约，token 变更先检查其他使用者。统一数字单位、小数、日期、金额对齐和状态语汇；长中文、负数、空值、多行错误都要有位置。

参考 [组件模式](component-patterns.md) 选一个适配内容的结构。数据比较适合对齐的表格，不为凑卡片拆散关联；大图叙事可以直接排版，不强加边框。渐变、衬线、圆角或阴影是否保留取决于品牌、层级与可读性，不设通用审美禁令。

删掉重复说明、无作用外框和竞争的动作，但保留对象名、判断依据、当前状态、错误原因与主要动作。只在一个合适细节建立记忆点，例如完成反馈或内容展开；不强制每屏一个特效或三处动画。

## 看实际结果

在相同内容、视口、状态和字体加载条件下对比基线与修改版。查看正常与长内容、窄屏、键盘焦点和减少动效；对问题提供区域、影响与修复证据。保留有依据的偏好，不用主观分数覆盖功能缺陷。修复具体问题后复查受影响路径，不为了“更高级”无止境改方向。
