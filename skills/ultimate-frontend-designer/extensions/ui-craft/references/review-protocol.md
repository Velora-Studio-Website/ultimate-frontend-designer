# 产物审查与证据协议

审查对象是实际产物及已约定任务。按影响范围选择路径和状态，不将本参考升级为每次都要执行的长清单；遵守 [GUIDE](../GUIDE.md) 与 UFD 原有 image-first 流程及 Design/Build 门禁。本文独立编写，不包含专有 Pro 内容，不声称对等，也不自行增加生成消费或强制三种方案。

## 两条证据路径分别成立

**视觉审查使用真实截图。** 在实际可运行页面中打开受影响视图，用代表性数据和对应状态捕获截图，记录版本或修订、页面、视口及状态。小屏变化需要相应视口的真实截图；有交互变化时，补充触发后的状态。截图不能由设计稿、生成示意图、旧版本图片或组件实验室演示替代。

**行为验证实际走完路径。** 从明确入口执行操作，记录预期、实际结果与恢复出口。保存类动作确认权威响应，并按任务需要重新读取或重开对象；错误恢复、权限和竞态只在真实触发或明确标注的模拟条件下报告。截图只证明被捕获时的外观，不能证明持久化、键盘可达、焦点管理或竞态安全。

构建、静态检查、HTTP 成功和工具安装分别记录自身结果，不可合并成浏览器验收。即使同一执行者承担两条路径，也应分别记录证据与结论。新增或运行测试、启用工具及外部服务均服从当前任务授权，本协议本身不授予权限。

## 隔离的审查者

当宿主提供真实独立审查能力且任务范围允许时，给审查者同一份目标、约束、验收条件、实际截图和必要上下文，先不提供制作者的自评或偏好方案。可用代码或页面观察解释截图问题，但不能拿实现意图覆盖观察结果。审查者返回可定位的问题；制作者负责修复，综合者按证据确认处理结果。

当独立审查不可用时，明确写 `UNAVAILABLE：独立审查者不可用`，并记录具体限制。可执行单模型多视角自查，清楚标为自查；不能称为独立评审、专家共识或已经完成的代理调用。若独立审查是明确验收条件，保持该条件未满足；否则交付现有证据及残余限制，由任务约定决定是否完成。

## 发现必须能推动修复

每项发现使用以下紧凑记录，不给虚构的分数、平均分或主观百分比：

> **位置与条件**：页面／组件、视口、状态和触发方式。  
> **证据与影响**：截图标识或实际操作记录；违反哪条任务约束，阻断什么动作或造成什么误解。  
> **修复与复查**：具体调整、受影响路径、同条件复查结果和证据位置。  
> **残余限制**：仍未知的环境、设备、依赖或未覆盖分支；无则明确写无已知残余问题。

当发现是偏好时，标明偏好及取舍，不冒充缺陷；当证据不足时，给出最小区分性观察或复现动作。涉及隐私的截图须按任务要求脱敏，不能为留证暴露真实个人信息或凭据。

## 按变更范围审查

| 变更条件 | 需要的视觉证据 | 单独的行为证据 |
| --- | --- | --- |
| 局部视觉调整 | 受影响组件在实际页面的前后截图；布局可能溢出时补小屏 | 确认相关操作及焦点没有被遮挡或丢失 |
| 表单、弹窗或流程改动 | 关键步骤、反馈和错误位置的真实截图 | 走通主要完成路径，检查受影响的取消、失败恢复和键盘路径 |
| 保存、异步或权限改动 | 用户能区分处理中、失败及确认结果的状态截图 | 确认写入与读回；针对改动检查重复提交、旧响应或权限失败分支 |
| 工作区或结构改造 | 主要布局及小屏折叠截图，使用相同任务数据比较 | 确认导航、筛选、选择、草稿和返回上下文；覆盖受影响旧入口 |

当只改文案或纯文档时，不强迫搭建浏览器或截图；核对实际文本、目标文件及链接范围即可。当任务禁止执行时，记录哪些验证未执行及原因，不能补写结果。若实际页面无法启动，记录启动失败与环境限制；静态审阅不能升级为真实截图审查。

## 修复、复查与停止条件

1. **先处理影响最大的具体问题。** 阻断任务、数据丢失、权限错误或无法恢复的问题先于装饰偏好；先保留有效成果，不因局部问题重做全部产物。
2. **修复后复查原条件。** 用相同入口、数据、视口和状态重现原问题；涉及行为时重新执行受影响路径。修订已变化时更新证据归属，不能拿旧截图证明新代码。
3. **只扩展必要覆盖。** 修复影响相邻状态、共享组件或其他断点时补相应验证；未受影响且版本适用的证据可复用。不设固定“通过轮数”，一轮无缺陷或多轮修复都不能自动决定通过。
4. **依据条件结束。** 必须条件均有对应证据、重要发现已修复并复查，才可报告通过；仍有具体可修问题就继续。外部依赖阻塞时完成可独立工作，并明确未满足条件、影响与下一步所需输入。

最终报告使用准确状态：`PASS` 仅对应有证据满足的条件；`FAIL` 表示观察到违反；`UNAVAILABLE` 表示所需环境或能力不可用；`UNKNOWN` 表示结果证据不足。报告交付范围、证据位置、重要修复和最强残余限制，不以整体 PASS 掩盖未验证的强制条件。

状态分支按 [交互状态与恢复](interaction-states.md) 选择；布局及改造范围按 [工作区与改造](workspaces-renovation.md) 确定。[组件实验室](../assets/component-lab.html) 可用于讨论局部模式，其演示结果不能代替产品实际页面的验收。
