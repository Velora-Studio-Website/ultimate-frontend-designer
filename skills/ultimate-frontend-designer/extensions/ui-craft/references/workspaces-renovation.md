# 工作区选型与改造

以用户最常重复的任务、信息关系及操作代价选择布局。以下是十种可组合的任务原型，不是必须产出的十套页面；边界规则见 [GUIDE](../GUIDE.md)。本参考独立编写，不包含专有 Pro 内容或对等承诺，也不替代 UFD 的 image-first 流程与 Design/Build 门禁。

## 十种任务布局

| 原型 | 何时选用与空间优先级 | 小屏折叠 | 误用信号 |
| --- | --- | --- | --- |
| 1. 队列—详情处理台 | 连续处理工单、申请、消息，需保持队列上下文；列表保留状态、优先级与下一项入口，详情承担决策 | 列表与详情分路由或分屏，返回恢复筛选、位置与选中项 | 每项只是静态链接，却长期占用一半屏幕展示空详情 |
| 2. 可编辑数据表 | 用户需要跨记录比较、排序、批量修改；字段与行操作稳定，清楚表达选择范围 | 优先关键列，次要字段进详情；确需二维比较时保留有提示的横向滚动 | 用卡片替换后无法比较，或把长篇编辑强塞进窄单元格 |
| 3. 阶段看板 | 任务有少量明确阶段，用户经常移动任务或识别拥堵；列代表业务状态 | 单列阶段筛选或分组列表，保留计数与“移动到”操作 | 列只是装饰分类、状态太多，或只有拖动才能更新 |
| 4. 时间排程台 | 时间、时长、重叠或资源冲突直接决定任务；日历与冲突提示占主要空间 | 默认议程列表，按需切换日期；编辑时间可用表单完成 | 任务没有时间约束，却为了视觉把普通清单塞入日历 |
| 5. 资产库与检查器 | 先浏览或筛选图片、文件、素材，再检查元数据和使用关系；预览与筛选优先 | 网格或列表浏览，检查器进入详情页，返回保留选择 | 把密集数值比较做成大图卡，或缩略图无法区分对象 |
| 6. 文档编辑器与大纲 | 长文写作、结构导航、批注或版本恢复；正文宽度与持续编辑优先 | 正文主视图，大纲及批注按需展开；键盘出现后工具仍可达 | 工具栏和面板挤压正文，选区因面板切换而丢失 |
| 7. 空间画布与属性栏 | 节点、图形、关系或位置本身是数据；画布主导，属性栏跟随选择 | 聚焦选中对象，属性抽屉可关闭；提供对象列表和数值编辑作为替代 | 本可用顺序表单完成，却要求用户缩放、拖拽寻找入口 |
| 8. 分步办理流程 | 填写有依赖、资格分支或高代价确认；当前步骤、进度与摘要明确 | 单列步骤，摘要可展开；返回上一步保留输入和校验结果 | 将三个独立字段拆成多屏，或步骤顺序没有业务依据 |
| 9. 监控与异常下钻台 | 用户先判断是否异常，再定位原因和采取动作；关键阈值、时间范围和下钻优先 | 先异常与核心指标，再图表和明细；筛选条件可见 | 只有漂亮数字，没有定义、更新时间、比较依据或处理入口 |
| 10. 配置与策略控制台 | 用户按主题修改偏好、权限或策略；导航稳定，作用范围及保存边界明确 | 分组索引进入单个设置页；离开时保留或明确处理草稿 | 把即时生效与需保存的字段混在一起，或不说明影响哪些对象 |

当任务同时符合多个原型时，用频率最高且失败代价最大的动作决定主布局，只为必要的第二任务增加面板。若无法说明面板之间需要共享什么上下文，就先采用页面导航。不要强制产出三种方案；有真实争议时才比较能改变决定的备选。

## 三种改造模式

### 视觉焕新：目标是辨识、层级与一致性

当流程正确、用户主要抱怨密度、可读性或风格时，复用路由、数据契约、组件行为和已验证状态，优先调整设计令牌、排版、间距、颜色及必要的表层结构。先检查原组件是否能承载改进，再决定局部重写。

若焕新需要改变保存时机、导航顺序、选择规则或权限入口，已跨入流程修复或新增功能；明确范围后再实施。比较同一数据、视口和状态的前后截图，并分别确认原有关键行为，不能用外观接近证明行为保留。

### 流程修复：目标是减少真实阻断

当用户卡在查找、填写、提交、确认或恢复环节时，先复现起点、阻断动作与预期终点，沿该路径修复信息架构或交互。复用仍有效的字段、服务调用和领域规则；只调整造成阻断的步骤、默认值、反馈或恢复出口。

若删除步骤，确认其中的校验、权限、审计或信息收集仍有落点；若合并页面，确认深链接、返回与草稿恢复仍成立。验收使用原失败路径及受影响的相邻路径，不能以少一次点击作为唯一成功标准。

### 新增功能：目标是完成新增任务

当需求确实增加对象、动作或工作阶段时，先确认真实数据来源、权限、保存契约和失败边界，再将入口放到用户产生该需求的位置。优先扩展现有布局和组件；独立的新任务才引入新工作区，不为单个按钮重建整套壳层。

若后端能力缺失，将演示与可用功能明确区分；演示数据、不可执行动作及未接通路径不得包装成已上线能力。新增流程需要自己的成功、失败和返回路径，并检查它是否改变既有默认值、路由或选择状态。

## 复用与行为保留的判定

- 当开始改造时，记录受影响入口、关键动作、数据写入、权限及恢复行为；仅围绕该范围读取与修改，不顺带重构无关模块。既有缺陷是待确认问题，不能自动当作新规范。
- 当复用组件时，确认其语义、键盘方式、响应式及状态接口适合任务；外观相似不能证明适配。若必须替换，明确替换原因及可能受影响的调用点。
- 当布局改变时，跟踪对象 ID、筛选、选择、排序、草稿和焦点落点；允许表现改变，但任务的有效输入、保存结果与返回上下文须符合已确认约定。
- 当涉及图像时，沿用 UFD 已确认的视觉资产决策与阶段流程；必要资产不能用装饰占位符冒充完成。本参考不追加生成额度、变体数量或额外消费。

状态细节见 [交互状态与恢复](interaction-states.md)；实际改造结果按 [审查协议](review-protocol.md) 留证。
