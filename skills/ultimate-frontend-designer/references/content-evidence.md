# 内容证据：从可追溯事实到两道交付门

本指南用于品牌页、产品页及业务界面的内容准备、设计评审和实现验收。
目标是让每个影响决策的句子有依据，让缺失资料成为明确任务，而不是被漂亮排版藏住。
本文的编号、产品和业务场景均为教学模拟，不代表任何真实品牌、客户或经营结果。
行业取舍见 [行业内容](industry-content.md)，表现验证见 [专业工艺](professional-craft.md)。
外部规范的适用边界与验证方式见 [专业来源](professional-sources.md)。

## 1. 先建立事实台账

适用问题：用户口述、旧稿、截图和官网内容互相冲突，却已经开始写销售标题。
方法：将输入拆成可独立判断真假的 claim；一个编号只记录一个断言。
例如“支持批量导入且适合所有企业”必须拆成能力与适用范围两个 claim。
台账写进项目已有 brief 或内容记录；本指南不要求另建一套阶段状态。

| 字段 | 记录规则 | 教学模拟值 |
| --- | --- | --- |
| claim_id / claim | 稳定编号；明确对象和动作 | C01：工作区支持 CSV 导入 |
| status | 下表四种之一，不能留空 | user_supplied |
| source / locator | 原始出处及页码、段落或消息位置 | 用户本轮需求第 2 段 |
| scope / conditions | 版本、地区、套餐、对象、限制 | 套餐和文件大小尚未说明 |
| checked_at / valid_until | 核对时间及失效触发条件 | 本轮接收；版本变化重核 |
| owner / next_action | 谁能补证，下一步是什么 | 产品负责人确认限制 |
| usage / permission | 内部或公开；引用、肖像、商标授权 | 仅内部草稿 |
| destination | 哪些页面与状态使用此断言 | 功能区、导入说明 |

| 状态 | 含义 | 允许怎样使用 |
| --- | --- | --- |
| user_supplied | 用户明确提供，但尚未独立核验 | 保留出处；按风险与发布许可决定是否采用 |
| verified | 已用适当证据核对，并记录适用条件 | 在已证实范围内陈述，不扩大承诺 |
| assumption | 为推进结构而作的工作假设 | 仅用于已标明的设计推演，不转成真实产品承诺 |
| pending | 关键事实尚未得到足够资料 | 记录问题和责任人，相关承诺暂不输出 |

失败：把“用户说过”直接改成 verified；把“未找到反证”当作证明。
验收：随机挑一条公开承诺，能从界面回到台账、原始出处和适用条件。

## 2. 对来源做三轴判断

适用问题：找到一个看似权威的网页，却不知道能不能支撑当前句子。
可信度：先找对此事实有直接责任的一手资料；法规、厂商能力、用户需求分别找各自拥有者。
利益关系：厂商能证明自己提供什么，不能单凭自述证明“市场第一”。
独立性：多篇转载同一新闻稿只算同一证据链，不算多方验证。
时效性：记录内容版本、发布日期、访问日期；访问日期不能替代内容生效日期。
价格、库存、配送和套餐应在发布或交易前重核；字体建议等稳定知识按变更触发复查。
不要给所有材料统一套“有效 30 天”；失效条件由决策风险与业务更新频率决定。
claim 粒度：证据覆盖哪个地区、样本、版本和时间，句子就写到哪个范围。
把性能测试结论限定为对应环境；把研究相关性写成相关性，不改成因果承诺。
冲突处理：并列记录两个来源、差异与时间，不选择更好看的数字。
失败：拿旧版企业套餐截图证明当前免费版能力；拿行业平均值证明某个客户结果。
验收：每条高影响 claim 都说明“为何此来源能回答此问题”及“什么时候必须重查”。

## 3. 研究交给 brief 的最小包

适用问题：研究链接很多，设计师仍不知道首屏该说什么。
先写用户问题：“我能否把已有数据迁入，并在失败时恢复？”比“打造智能体验”可执行。
每个问题配一条候选回答、claim_id、证据位置、未知条件及下一步动作。
把竞品材料用于辨认用户习惯和差异，不复制对方的客户、定价、资质或效果。
研究输出必须区分 observed（实际观察）、source_claim（来源声称）和 interpretation（分析判断）。
截图证明截图里出现过某个状态，不能单独证明该功能已接通或能处理真实数据。
brief 用一句话界定受众、任务、目标结果、设备与明确不做的范围。
再列内容优先级：完成任务必需、辅助比较、可延后了解；不要先规定必须有六张卡片。
将审核、版权、敏感信息和公开许可作为字段保留，核验不等于获得转载许可。
失败：交接一堆 URL，要求写作者自行猜测哪些结论已被认可。
验收：接手者只读 brief 就能指出主动作、主要疑虑、可用证据和阻塞项。

## 4. 内容覆盖矩阵决定页面结构

适用问题：页面每块都有标题，用户却无法判断是否适合自己。
先列用户决策问题，再列回答所需内容、证据和操作，不按模板栏目倒填文案。

| 用户问题 | 应交付内容 | 证据/状态 | 页面动作 |
| --- | --- | --- | --- |
| 是否处理我的任务？ | 具体输入、过程、输出及不适用条件 | 能力 claim + 范围 | 查看对应流程 |
| 为什么相信？ | 可核对的样例、方法或结果口径 | 证据位置 + 公开许可 | 展开依据 |
| 代价与限制？ | 费用、时间、权限、风险 | 当前政策或 pending | 比较条件/补充询问 |
| 下一步会发生什么？ | 动作结果、所需输入、后续路径 | 已接通行为或模拟标识 | 开始/提交/返回 |
| 失败怎么办？ | 原因、保留内容、恢复动作 | 状态规则与测试结果 | 修正后重试 |

方法：每个必需问题至少有一个清晰回答；回答附近保留影响判断的限制。
同一个证据可支持多个位置，但修改时要追踪所有引用位置，避免标题与 FAQ 冲突。
失败：把“常见问题”当作存放所有关键限制的角落，首屏仍作绝对承诺。
验收：遮住装饰和配图，用户仍能说明对象、适用条件、代价及下一步。

## 5. 缺料时选择可逆路径

适用问题：交期已定，客户案例、价格或真实截图尚未到位。
关键交易条件缺失：保留 pending；阻止依赖该条件的上线承诺，先做无关布局和状态。
案例缺失：展示已核实的服务流程、交付范围或明确标注的过程演示，不捏造客户评价。
价格缺失：真实业务允许询价时写清询价所需信息；否则保留内部占位，不擅自改业务模式。
截图缺失：可用文字流程或明确模拟界面检验结构，不能称为真实运行截图。
数据缺失：显示“暂无数据”的真实状态，或在获准的演示环境标“模拟数据”。
授权模拟：先确认模拟范围，在演示入口及相关数据附近明确标识，导出也保留说明。
面向真实业务的交付：移除模拟背书和未经证实的指标；不能仅靠交付说明解除误导。
缺料清单必须写影响、负责人、下一动作和恢复条件；没有负责人就回到任务所有者。
失败：将占位姓名换成真实客户 Logo；将模拟增长曲线混进真实业绩区。
验收：资料继续缺失时，交付仍诚实可用；补料后只需替换对应内容而不推翻整个结构。

## 6. 文案前后对照：删掉无依据的跃迁

以下都是教学模拟；“修改后”也仅在所列前提成立时可用于真实产品。
例 A 前文：“行业领先，一键迁移所有数据，效率提升 300%。”
问题：领先无比较范围，“所有”无兼容边界，数字无样本与基线。
例 A 已有资料：用户仅说明支持 CSV；未提供运行记录、性能测试或文件限制。
例 A 内部草稿：“通过 CSV 导入已有记录。”标记 user_supplied，并挂待核验限制。
例 A 对外候选：能力核验后写“导入 CSV 记录”，在操作前展示已确认的格式与容量要求。
例 A 没有确认前：只做标明模拟的导入流程，不能展示“已成功迁移”的真实业务反馈。
例 B 前文：“深受上千家企业信赖，立即咨询，明天上线。”
例 B 已有资料：只有获准描述的需求梳理、原型评审两项服务，没有客户数或工期证据。
例 B 后文：“先明确任务与范围，再评审关键流程原型。”前提是两项服务确属已确认范围。
例 B 动作旁补充：按真实流程说明咨询需要什么、何时答复；答复时间未知则不承诺。
失败：只把“300%”改成“显著”，仍保留未被支持的效果断言。
验收：逐句检查名词、动作、数量、比较词及时间词，每个都能找到相应依据。

## 7. 接入 Design Gate 与 Build Gate

研究完成条件：问题有覆盖，关键 claim 有出处，冲突有处理路径；未知不冒充已知。
brief 完成条件：主任务、内容范围、缺料策略、公开许可及模拟边界可被复述。
Design Gate 内容检查：用真实长度的已确认中文验证结构，关键条件不靠脚注才能找到。
Design Gate 内容阻塞：核心承诺 pending、模拟未标识、证据无法定位、CTA 结果未定义。
非阻塞缺料：可隔离的次要素材有负责人和诚实替代，可继续制作不依赖它的部分。
Build Gate 内容检查：成品逐句对账，链接能到达依据，日期/单位/套餐与真实逻辑一致。
Build Gate 行为检查：动作有可观察结果，空错状态无虚构成功，刷新与失败路径不丢必要输入。
发布前重核：变化快的事实和公开许可；设计时验证过不能自动继承到发布日期。
记录 PASS/FAIL/UNAVAILABLE/UNKNOWN 及证据位置；文字审读不能代替运行和视觉证据。
内容变化按依赖回检：改价格查比较表、结算、FAQ；改术语查导航、错误、帮助和搜索。
指南自身完成不代表项目过门；主流程沿用既有 Gate 与授权，不创建平行状态机。
