# 动静与设备决策、页面设计、静态素材

对应 `motion_decision`、`page_design`、`static_assets` 三个阶段。两种模式都必须走完这三步，non-animate 不等于不生成图片。

## 参考分析与页面节奏

用户提供参考且需要提取设计语言时，可用 stylejuicer 的公开页面取证方法。只分析授权范围内的可访问内容；引用具体视口和状态，把直接观察、重复出现、推断和未知分开。抽取构图机制与约束，不复制品牌、文案、素材或独特整页构图；缺失截图不能当成已看过。

每个区块应回答一个用户问题，并为下一步提供信息。营销页可按理解价值、查看证据、作出决定组织；操作页按任务顺序组织，不套信任栏、定价、评价等营销模板。缺少真实证据时调整内容结构，不生成假证据填空。

为关键区块明确焦点、阅读顺序、图文比例、主要行动与衔接关系。Hero 可是居中、叠放、偏置、满幅或极简构图，依据内容选择，不机械排斥左右分栏。通过尺度、密度和留白形成节奏；功能型界面的稳定结构比强制每区换构图更重要。

保持整页总览 + 必要分区细节 + 目标设备构图。只有细节读不清或结构不同才拆图，不强制每节一张横图，不默认六/八节，也不强制四种特色组件。跨图固定字体角色、CTA 家族、配色、圆角与素材语言。移动端布局按阅读与操作顺序重新组织，不能把桌面截图简单缩小。

布局、对齐、圆角与渐变按内容、层级和品牌判断；不为反套路强制改掉合适的常见结构。具体方向契约见 design-foundation 分册。

## 布局与素材返工

用间距先分组、共享边缘建立对齐，再按需要用背景和分隔线；组间距离应能清晰区别组内关系。先沿用项目密度体系，不把固定像素配方强加给密集工具。断点以内容容纳能力确定，记录实际检查宽度；支持多语言时采用逻辑方向属性，检查长标签、RTL（适用时）、缩放和关键操作被遮挡的情况。

### 技术栈与条件性单文件交付

已有项目沿用框架、组件、路由与样式，Reuse > Extend > Replace。新项目选择满足内容、交互和维护需求的最小方案：静态 HTML/CSS 可足够；有实际需要才引入 React、TypeScript、构建器或组件库。不强制 Tailwind、shadcn 或 `@/` 别名。样式作用域与 tokens 遵循项目模式，检查全局级联和组件覆盖，不声称某种 CSS 工具能消除全部冲突。

只有适合离线静态分发或明确指定时才提供 `bundle.html`；在用户预期的 file:// 或 HTTP 打开上下文实际测试导航、资源、字体和交互。披露 backend/API、远程字体、网络请求、认证、跨源和路由依赖；内联构建不等于移除这些限制，不保证任意环境完美运行。

素材请求先区分新生成、参考编辑、局部修补和构图变体。编辑时列出保留项和修改项，保持主体、产品结构、标识与已确认图像语言；优先修正失败部分，避免无关全图重做。蒙版、多参考与输出参数只有实际工具支持才使用。gpt-image/API 路线按主文件解析；已有授权批次可执行，编辑技巧不额外授权新渠道或费用。

## 分离视觉批评与工程验收

Design Gate 先检查用途、信息层级、视觉识别、图文一致性与关键假设；不能只数文件。implementation 后按同一批目标页面集中检查，再修复并复核受影响部分：

视觉对照时实际打开当前设计稿与实现截图，匹配视口、主题、内容、交互状态、裁切与像素密度；先检查整页构图，再查看字体、Logo 与关键组件细节。有意的适配差异记录理由，修复后重新捕获受影响状态，不能只凭记忆或源代码声称还原通过。

每项先记录 applicability 与理由，再记录 method、status、evidence、repair、recheck；不适用不冒充通过。第一轮集中检查，修复后复验；必要缺陷仍在就继续，不设硬性轮数上限。

| 检查 | 可观察的验收证据 |
| --- | --- |
| 视觉还原与内容 | 实际页面对照当前设计版本，核对内容覆盖与有意调整 |
| 主要键盘任务 | 从入口到完成或错误恢复，只用键盘；焦点顺序与可见性、控件名称清楚 |
| Overlay（适用时） | 打开焦点进入合理位置；模态有必要的 focus trap；Escape 关闭并返回触发者；非模态不盲目 trap |
| 表单与状态 | 标签/名称与输入关联；错误可定位，验证和异步状态由适当 live region/语义通知；不只靠颜色 |
| 文案与 reflow | 真实长文、CJK/混排、适用语言与缩放下仍可读、可操作，记录实际视口/缩放条件 |
| 响应式结构 | sticky/fixed 不遮焦点和操作，检查横向溢出、裁切与滚动容器 |
| 指针替代 | hover/拖拽/手势功能有键盘、触控或等价操作，不把信息藏在 hover 中 |
| 颜色 | 测量真实前景/背景（含透明叠层、图片）组合，记录数值、阈值及条件 |
| 动效、3D 与加载失败 | reduced-motion 有等价信息；中断/重复输入正确；媒体、字体、脚本与数据失败可恢复；3D 有静态或文本替代 |
| 图表与性能 | 保留目标分析任务；SSR/水合、尺寸和加载策略在实际栈检查；性能数值仅来自实测 |

FAIL、UNKNOWN 或 UNAVAILABLE 的必要检查阻止完整验收；说明受限交付、具体阻塞与未验证范围。可选用户研究不足不冒充结果，也不自动冻结未要求研究的工程交付。风格偏好不是缺陷，不发明分数或研究数据。

工程审查可使用 web-design-guidelines，先加载适用规则，再读项目的全局样式和共享组件，避免将全局已处理的问题误报为组件缺陷。Impeccable 的视觉判断与指南证据互补，不用其中一种代替另一种。定位到实际页面/组件；代码问题记录已读的 file:line。报告区分静态检查、浏览器实测、用户测试和未验证项。

用“位置 / 问题 / 用户影响 / 依据 / 修正 / 复核结果”记录根因，重复症状合并。未解决的关键失败阻止对应范围通过，次要审美建议不无限拖延交付。任务只是审查时只报告；已授权实现/修复时处理范围内缺陷，重大视觉变更先更新设计依据。

## 动静选择与设备范围

先用已有选择和代选授权确定 animate/non_animate，并在 motion_decision 分开记录 UI motion、3D、generated_video 及理由；只有实质缺口才与 intake 合并询问。没有答案且没有代选授权时保持 pending，不默认生成视频。用户授权你自行决定时，记录决定与理由，标为 `delegated_decision`，不要写成用户确认。

确认主要体验是电脑浏览器、手机浏览器还是两端都要，设备范围与功能范围分开记录。"Web App"不自动等于手机端，也不等于原生应用；存在影响范围的歧义时用一句话确认是移动网页体验还是带业务功能的网页应用。Higgsfield 工具里的产品类型也不等于 desktop／mobile 范围。

non-animate 仍继续图片生成与静态素材制作，只是不进入视频生产。设备未限定时采用响应式 desktop + mobile，并记录为设计假设。静态版默认没有装饰性动效、自动播放、持续动画、视频背景、视差叙事或滚动视频，也不要悄悄加自动轮播；按钮状态、键盘焦点、表单反馈、菜单和手动切图仍然要可用，默认即时反馈。

两端都要时分别规划构图、裁切、文字安全区和媒体负载，而不是把桌面稿简单缩小。最终设备与动静规则回填设计系统。

验证按风险分配：主视口真实走到主要结果；任务未限制单端时，另一端只查代表视口和主要状态。再从最长/空/错误恢复等状态里选一个最可能破坏阅读或主操作的补查。Canvas/手势、复杂多栏、移动虚拟键盘、多屏导航、壳内滚动、特殊视口确有风险时，各补对应检查；通过即停止扩展。

## 内容完整性检查

按 [内容与证据](content-evidence.md) 在 brief 维护事实与覆盖表；按 [行业内容](industry-content.md) 选择专业信息，不将电商清单套给所有产品。区分 user_supplied、verified、assumption、pending，行业通用知识不能证明某家企业的能力或业绩。

Design Gate 对照事实/覆盖表与图片稿，检查主张、限制、信息顺序及缺口；Build Gate 用同一表核对实际页面是否省略关键说明、改变单位或将假设表现为事实。记录逐项结果和受限范围。

在 brief 整理内容，在 page_design 生成前核对，在 prebuild_review 验收；不增加阶段或额外强制审批。沿用主文件的“内容范围与视觉确认”规则。用户只选风格时保留已有任务范围；已有明确内容范围、自主设计授权或精确复刻要求时直接沿用，不重复询问。

1. 根据页面用途列出用户需要理解的信息、关键疑问和主要行动，映射到页面或区块。可在 brief 使用“用户问题／所需信息／页面或区块／事实来源或待补状态”的表格；不另建竞争的规划文档。
2. 电商按适用性检查：产品是什么、用途与适用场景、真实特点及证据、使用方法、规格、包装内容、选项比较、保养、价格与配送退换、常见疑问、购买入口。这是候选问题清单，不是必做区块模板；可以合并、分到其他页面，或记录不适用理由，不强制长页面、多页面或重复 CTA。
3. 缺少资料时区分已确认事实、设计提案与待提供信息。先保留必要的信息结构并推进不依赖缺口的工作；只询问真正阻塞的资料。不要从产品外观推断未经确认的功能，也不要为了凑满页面编造评价、参数、优惠或政策。带待补标注的审阅原型只按该范围验收，不冒充可上线商业站点。
4. 将内容覆盖表、页面顺序及关键文案要求写入页面图片生成提示词。长页使用整体总览加必要分区稿；不能因单张图片长度、清晰度或生成能力限制，擅自删减约定内容。已有方向稿只覆盖部分内容时，保留已选视觉语言，补设计缺失部分。
5. Design Gate 对照覆盖表与页面稿检查：关键问题是否得到回答，信息与行动顺序是否成立，缺口是否如实标注，遗漏是否有范围依据。只有首屏、细节、配色等少量区块时，也必须按任务判断是否足够，不能自动视为完整电商网站。发现缺项回到 brief 或 page_design 补齐；用户明确要求简版时，按简版范围交付并准确命名。

## 完整页面设计

根据当前设计系统，用图片模型生成完整高保真页面方案：单页覆盖首屏到页脚，多页覆盖约定的页面类型，功能型应用覆盖主要任务界面与必要状态。长页面用整体总览加分区细节图；只做一个 Hero 不算全站设计，把整站压成读不清的长图也不算。

每个区块明确内容目的、文字与图片的关系、CTA、图片角色、比例、裁切和目标设备布局。图片与布局一起设计，不要先写代码再找图填空。

电商页面的价格、选项、库存、配送、评价和购买能力只能使用真实资料，缺失项在设计审阅里明确标注"待提供"。用户明确允许带标注的原型时可以按该范围制作，但不能称为可上线的商业页面。

animate 按所选 UI motion/3D/视频说明触发、保持静态的区块、文字叠层与 reduced-motion 等价布局；只有视频已选择才规划视频叙事和滚动关系，页面不能依赖媒体才能理解。

退出条件：约定页面或关键界面都有完整设计；内容覆盖表已核对，关键问题、必要信息和主要行动无未经说明的遗漏；内容映射回 brief；目标设备的主要布局已确定；所需独立素材清单已形成。

## 静态素材

按页面实际需要生成 Hero、产品图、细节图、场景图、横幅、分类图、功能插画、背景、纹理与品牌图形。数量由页面长度、内容、产品数量与构图需要决定，不固定数量，不凑数，也不默认只做一张 Hero。已完成的设计系统板、字体板与 Logo 不重复生成；已有合格素材优先复用，不为了"全 AI"重做真实产品照片或标准功能图标。

为全站建立并复用 Visual DNA：品牌、主体或产品结构、比例、材质、配色、光线方向、镜头语言、环境、纹理与图像处理。每张图明确哪些必须保持不变、哪些允许变化。

真实商品展示不得因生成而改变实际外观、包装、功能或配件；没有可靠产品参考时，概念图必须标明用途，不能当作真实商品照片。数据图与参数说明依据真实数据制作。

分别检查 desktop 与 mobile 的焦点、主体完整性和文字安全区。能通过合理裁切兼容时复用；确实不兼容才生成设备专用版本，并把新增生成计入已授权范围。

页面效果图、设计板与生产素材分开保存。素材必须可独立使用，不要把整页截图切片当作 UI。图片里的网页文字不是最终文案来源。

退出条件：当前范围所需图片已生成或有可复用来源；独立文件可访问；一致性与目标设备构图已检查；素材清单已更新。只有 generated_video.selected 显式为 false 且记录理由（包括已确认的 UI-only animate），完成本阶段后才直接进入 prebuild_review；keyframes/video 记 not_applicable 和理由。selected=pending 保持未决，允许独立准备，不按 false 跳过；若可能实质改变必要素材，不能声称完整 Design Gate 通过。selected=true 继续关键帧与 H3 视频生产及验收。


### 数据可视化工程落地与水合安全 (Data Visualization & Hydration Safety)

按实际框架区分布局/状态与绘制层。浏览器 API 在合适的客户端生命周期或边界内访问，清理监听、动画与资源；稳定初始 markup，服务端与客户端初始数据一致。支持 SSR 的图表在有益时保留 SSR，不为所有图表关闭它。Next.js 只有真正依赖浏览器且无法 SSR 的模块才在适当 Client Component 内 `dynamic(..., { ssr: false })`，不可从 Server Component 使用该选项，也不是通用水合修复。其他框架遵循自身生命周期。

URL 只保存可分享、非敏感的筛选/时间范围等值，验证和限定输入；不放凭据、个人信息、私密实体或临时 UI 状态。高频变化可 replace，重要导航可 push，遵循项目路由。移动端重排或等价表格须保留原来的趋势/比较任务，不能自动把图表藏入抽屉。

### React Bits 动效组件集成规范 (React Bits Integration & Performance)

结合 `react-bits-animation` 最佳实践：
1. 最小源码集成：只拷贝选定组件所需的精简源码，项目实际使用 Tailwind 时才复用其现有配置；否则将组件适配到现有 CSS、tokens 与组件约定，或选择兼容替代，不隐式引入新样式框架，禁止安装冗余三方包。
2. 防范布局偏移 (CLS)：动画容器必须显式定义 min-height 或骨架占位，避免组件加载或动画执行过程中产生页面跳动。
3. 减弱动效回退：所有 React Bits 动效必须检测 `prefers-reduced-motion`，在用户开启减弱动效时即时呈现最终静态状态。

### Cult UI 组件集成规范 (Cult UI Registry Integration)

当项目采用 React + Tailwind + shadcn/ui 体系时，可在 implementation 阶段按需引入 `@cult-ui` 组件：
1. **按需单组件安装**：通过 `npx shadcn@latest add @cult-ui/<component-name>` 引入。禁止整库预装，仅按当前设计稿映射到的具体区块拉取对应源码。
2. **Tokens 体系归一**：安装后立即检查生成的源码，将硬编码的 Tailwind 颜色或 Cult UI 默认暗色配置重定向至项目现有的 `tokens.json` 语义变量（如 `bg-card`、`text-foreground`、`ring-ring`、圆角半径与字体）。
3. **无动效与降级支持**：非 animate 模式或用户开启 `prefers-reduced-motion` 时，具有视差、持续流体、粒子背景（如 `bg-animated-fractal-grid`、`hero-liquid-metal`）的组件必须提供静态 CSS/图片等价呈现；文字滚动动效（如 `rolling-number`、`typewriter`）必须立即呈现完整目标文字。
4. **依赖隔离与防冲突**：Cult UI 会自动引入 `@base-ui/react` 或 `motion`。若项目已有 GSAP 或独立 Framer Motion 版本，注意锁定版本边界，不得引入重复甚至互斥的动效上下文或全屏滚动拦截器。
