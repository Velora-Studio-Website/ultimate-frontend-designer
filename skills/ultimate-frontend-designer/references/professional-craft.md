# 专业工艺：让资料约束转化为可验证设计

本册连接真实内容、布局、交互与性能，适用于设计评审及实现后验收。
方法与示例为原创工作建议；标准阈值及其来源统一见 [专业来源](professional-sources.md)。
资料状态见 [内容证据](content-evidence.md)，行业任务见 [行业内容](industry-content.md)。
本文不构成全站合规声明；静态稿只能验证静态稿能够呈现的性质。

## 1. 用真实中文推导排版密度

适用条件：英文模板替换中文、长商品名、业务术语和混排数据开始挤压布局。
收集实际标题、正文、错误消息与极长值，再设计层级，不拿短占位字测成品。
每种组件至少测试短值、典型值、长值及未知值，数量按业务真实分布调整。
正文可从 16–18 CSS px、1.6–1.8 行高试排；这是起点，不是 WCAG 规定。
长中文正文可先试每行约 24–36 个汉字，再用实际字体和阅读任务判断。
不能把 `ch` 宽度直接当汉字数量；数字、拉丁字母和字体回退会改变视觉密度。
标题换行按语义检查，避免品牌名、数值单位和关键否定词被孤立。
允许术语换行或提供完整说明；不要为保持卡片齐高而截掉决策条件。
英文串、网址与编号使用合适的断行策略；不可全局强拆所有单词。
原创示例：“仅管理员可导出已归档记录”不可裁成“仅管理员可导出…”。
若列表需要截断，详情必须能用键盘和触屏访问，不能只靠鼠标提示层。
失败反例：中文正文沿用极细字重和紧行距，标题漂亮但条款读不清。
修复：先放宽正文行距与容器，再调整装饰比例，保留完整关键条件。
验证：加载实际字体和回退字体，检查换行、数字列、缩放及中英文标点。
文字放大后检查实际任务，不因截图未溢出就推断可读性合格。

## 2. 从内容角色推导色彩与复杂背景

适用条件：品牌色、照片、渐变或视频同时出现，单一色板无法说明最终可读性。
先分配正文、辅助信息、动作、状态与装饰角色，再为角色选择颜色。
语义不能只依赖颜色；错误需有文本或图形等额外提示。
对比度核查的是最终合成后的前景与背景，不只是设计 token 的原始色值。
照片和视频需覆盖文字区域的不同亮暗位置与播放帧，不能只抽首帧。
可选修复：文字底板、局部遮罩、移动裁切或把关键文字移出背景。
原创示例：展览页用暖色作品照，预约说明放在独立实色面板，仍保留作品氛围。
遮罩透明度必须由实际样本验证，不能套一个百分比宣告所有图像都可用。
按钮普通态、悬停、焦点与按下态分别检查；不能只查默认静态截图。
错误红与成功绿需验证色觉差异场景，并核对实际状态词是否准确。
失败反例：把品牌亮黄设为白底正文色，再凭“大字应该够亮”放行。
修复：换深色正文或稳定底板，实际测量；阈值与例外回到来源核查。
验证：保留测量位置、前背景值、状态和结果，避免“已测对比度”的空结论。
深浅主题与图片更新会改变组合，相关变更必须重测受影响位置。

## 3. IA 必须包含状态、权限与恢复路径

适用条件：导航树已经画好，但真实操作仍会遇到空数据、等待和错误。
以任务为行、状态为列：初始、加载、成功、无结果、部分失败、权限不足。
再记录刷新、返回、链接直达和会话过期后的落点，检查用户是否失去上下文。
给每个对象明确名称与生命周期；列表、详情、搜索和消息使用同一术语。
区分“没有记录”“筛选无结果”和“无权查看”，三者需要不同下一步。
原创示例：筛选无结果显示当前条件与“清除筛选”；没有记录才引导创建。
载入失败保留用户已填输入，并根据实际支持能力提供重试或返回。
异步保存时展示处理中；只有收到可靠确认才显示已保存。
部分成功要列出完成与失败范围，不能用一个绿色提示吞掉异常。
对话框要定义开启、关闭、焦点移动及返回位置；模式选择参考 APG 对应组件。
原生链接用于导航、原生按钮用于动作，减少额外重造语义和键盘行为的负担。
失败反例：用不可聚焦的文字充当按钮，点击后页面状态无可见变化。
修复：落实可操作语义、明确反馈及恢复路径，再验证实际辅助技术表现。
验证：只用键盘走完整任务，记录焦点顺序、可见性、关闭及返回结果。
读屏检查名称、状态和消息；自动扫描通过不能替代这条任务测试。

## 4. 图表必须交代单位、口径与不确定性

适用条件：页面用数字支持比较、经营判断或效果承诺，视觉容易扩大证据力度。
先写问题与数据定义，再选图形；对比数量、时间趋势与分布使用不同表达。
最少标出指标定义、单位、时间区间、样本或覆盖范围、来源及更新时间。
金额说明币种及税费口径，百分比说明分母；平均值不能冒充所有个体表现。
原创示例：模拟导入失败率由 8% 降至 6%，变化为下降 2 个百分点。
相对降幅为 25%；两种说法不可混用，且该模拟不能成为真实产品成果。
缺失值与零值分开；没有观测不能连线假装连续，估算段使用明确不同的表达。
区间只在有统计依据时显示，注明区间类型；无数据时不要自造误差带。
预测明确标为预测并写假设；“区间”不天然代表置信区间或承诺范围。
条形图通常从零起点便于比较长度；若用其他刻度，说明原因与可能误读。
需要细微波动时可用折线局部尺度，但坐标与基线必须清楚可见。
多轴、面积和三维效果会放大解释负担，只有实际任务需要时才采用。
交互图提供可访问数据或等价说明，键盘与触屏也能读取关键点。
失败反例：把预测销售额与历史数据画成同一条实线，省略币种与样本。
修复：分段标识预测，补数据口径与假设，并核对导出后是否仍保留说明。
验证：独立复算一个点、一个汇总和一个变化值，核对筛选后的分母及单位。

## 5. 移动端完成同一任务，而非缩小桌面图

适用条件：手机用户仍需比较、筛选、填写和确认，不能简单隐藏桌面关键列。
列出桌面任务的输入、判断、动作和反馈，逐个映射到移动端的可达位置。
可以改容器和顺序，但不能无说明地删除限制、价格、错误信息或恢复入口。
原创示例：采购表格在手机上先列型号、适配与价格，展开后仍可查看完整规格。
若决策确实需要二维比较，可给表格局部滚动及清晰提示，保持页面其余部分重排。
软键盘弹出时检查当前输入、错误提示与提交动作是否可到达。
固定底栏需给内容留空间，并检查焦点、弹层和系统安全区之间的遮挡。
触控目标同时检查实际点击区域、相邻间距与误触，不能只测图标尺寸。
项目可选择更宽裕的触控尺寸作为产品目标，但不能冒称那是 AA 的统一强制值。
失败反例：手机隐藏运费和退换说明，保留巨大购买按钮，任务条件因此不完整。
修复：把影响购买的条件放回选择流程，再减少装饰与次要信息占位。
验证：真实窄屏或等效环境完成同一脚本，包含筛选、输入错误、返回和重试。
记录设备、视口、浏览器与输入方式；不能用一张手机截图证明交互通过。

## 6. 动效服务状态解释，并接受性能验证

适用条件：过渡、视差、视频或连续动画与阅读、滚动和输入同时发生。
先写动效目的：解释层级、反馈状态或保持对象连续性；没有作用就降低存在感。
同一任务设计低动态路径，尊重减少动态效果偏好，并确保功能仍然完整。
减少动画不等于只把时长设零；还要停止非必要循环、视差与大幅位移。
原创示例：记录归档后短暂收起行；低动态模式直接更新列表并显示可读结果。
常见优化起点是使用 transform 与 opacity，但图层、模糊和脚本仍需实测。
为媒体预留尺寸；避免晚加载横幅推动表单或支付动作的位置。
拆分长任务，避免滚动监听里重复读写布局；采用适合实际组件的调度策略。
失败反例：所有区块滚动才显现，脚本失效后正文一直透明。
修复：保证基础内容可见，再增强动效，并覆盖脚本异常及减少动态模式。
实验室测试记录设备与网络条件，性能预算由真实受众与任务决定。
上线后的体验结论需现场数据；LCP、INP、CLS 的推荐值与统计口径见来源册。
验证：录制关键交互的性能轨迹，查长任务、掉帧、布局偏移及输入反馈。

## 7. 工艺如何进入两道 Gate

DesignGate：真实中文、关键状态、移动任务和证据口径可审；动效有目的与替代路径。
BuildGate：复查渲染、键盘、读屏、触屏及性能，保留步骤与观察结果。
修复后重查受影响任务：改底栏查焦点遮挡，改图表查分母，改字体查重排。
报告已测页面、状态与环境；未测部分标 UNKNOWN，工具不可用标 UNAVAILABLE。
发现缺陷标 FAIL；局部通过只能写局部 PASS，不把检查清单冒充全站认证。
